# fix/PLD-381

## Branch Info
- **Repo:** PET-gcp_governance
- **Branch:** fix/PLD-381
- **Jira Ticket:** PLD-381
- **Ticket Title:** Fix WIF provider for ACA UAMI v1 token exchange
- **PR Link:** https://github.com/allicabankltd/PET-gcp_governance/pull/67

## Work Summary

- **2026-08-14**: Fixed WIF OIDC provider in `Terraform/resources_voice_of_customer_prod/gcp.workload_identity_federation.prod.tf` — switched issuer from v2.0 (`login.microsoftonline.com/{tid}/v2.0`) to v1 (`sts.windows.net/{tid}/`), updated attribute mapping from `assertion.azp` to `assertion.appid`, and added `tid` check to attribute condition. ACA UAMI mints v1 tokens where `azp` is absent and the client ID is in `appid`. Committed, pushed, raised PR #67, and added root-cause comment to Jira ticket PLD-381.


## Key Changes


## Notes / Learnings

- ACA managed identities always mint **v1 tokens** — `iss=sts.windows.net/{tid}/`, `appid` claim, no `azp`. The v2.0 issuer and `azp` condition only apply to user tokens or apps explicitly requesting v2.0 tokens via `api://` audiences.
- `az account get-access-token` from Cloud Shell returns a user token, not a UAMI token — it cannot validate WIF exchange for a container workload.

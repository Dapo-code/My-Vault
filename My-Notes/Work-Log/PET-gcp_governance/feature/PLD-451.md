## Work Summary

- **2026-08-17**: Analysed PLD-451 — VPC-SC blocking `svc-prod-voc-agent` on `bigquery.googleapis.com` in `abl-voice-of-customer-prod`. Created ingress rule `voc.agent.sa.ingress.yaml` scoped to that one SA, BigQuery only, with permission-based selectors (datasets.get, tables.get, tables.getData, tables.updateData, jobs.create, jobs.get) and access levels `nonprod_transit_network` + `prod_transit_network`. Committed and pushed to remote. Updated PLD-451 with rule shape and PR link.

## Key Changes

- `Terraform/service_control_policies_prod/policy_config/folder_prod_policy/abl_voice_of_customer_perimeter/ingress_rules/voc.agent.sa.ingress.yaml` — new ingress rule for VoC agent SA
- `Terraform/service_control_policies_prod/providers.required.tf` — azurerm provider pinned to `~>4`

## Notes / Learnings

- VPC-SC filters on identity, not network — WIF fix alone won't unblock this; a separate ingress rule is always needed for Azure-hosted workloads crossing the perimeter.
- Permissions-based selectors are cleaner than method lists when IAM roles are already tightly scoped; IAM remains the primary constraint.
- Access levels changed from `"*"` to transit networks — verify these cover the Azure container's egress path before closing.
